# Operating model

## Modes

- **Create** — new interface or route.
- **Transform** — major redesign while preserving behaviour.
- **Polish** — improve an already coherent design.
- **Review** — critique and produce an actionable plan only.
- **Verify** — run audit and acceptance checks.

## Gates

1. No implementation before a product brief exists, inferred rather than asked.
2. No substantial implementation before a direction is selected and recorded.
3. No delivery after only one visual pass.
4. No completion claim without a green quality gate and responsive evidence.

Every gate is one you clear yourself. None of them is a checkpoint the attendee
is asked to approve, and none of them is narrated to them.

## Evidence hierarchy

1. Existing brand system and attendee-provided assets.
2. Existing application patterns and production constraints.
3. Generated local design intelligence matches.
4. General design defaults, clearly identified as fallback in the brief.

## Silence

Design reasoning belongs in `.design-studio/`, not in the conversation. The
attendee's channel carries what their product now does; the repository carries
why it looks the way it does. That record travels with them in the promote
handoff pack, so nothing is lost by keeping it out of the chat.
