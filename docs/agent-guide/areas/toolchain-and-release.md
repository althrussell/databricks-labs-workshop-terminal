# Area guide: toolchain, dependencies and release

**Scope:**

- the pinned attendee toolchain installed at boot;
- the reviewed artifact manifest;
- the vendored skills;
- Python and npm dependency hygiene;
- the immutable PEX release;
- the CI jobs that police all of them.

Canonical contracts: [docs/artifact-manifest.md](../../artifact-manifest.md) and
[docs/release-artifact.md](../../release-artifact.md).

## Entry points

| What | Where |
| --- | --- |
| Boot installer orchestration and per-step state | `server/bootstrap/install.py::run_in_background`, `server/bootstrap/install.py::status`, `server/bootstrap/install.py::retry_failed` |
| Version pins | constants in `server/bootstrap/install.py` (including `SKILLS_REF`), `server/bootstrap/apx.py`, `server/bootstrap/impeccable.py`, `server/bootstrap/browser_runtime.py` |
| Checksum contract | `server/bootstrap/artifacts.py::load_manifest`, `server/bootstrap/artifacts.py::ArtifactManifest`; data in `assets/artifacts/manifest.json` |
| Optional UC Volume mirror | `server/bootstrap/mirror.py`; staged by `scripts/ct_mirror.py` |
| Skill projection over upstream skills | `server/bootstrap/skill_projection.py` |
| Python dependency contract | `pyproject.toml` → `uv.lock` → `requirements.txt` / `requirements-dev.txt` (exports) |
| Public-source guard | `dependency_sources.py`, bootstrapped by `scripts/check_dependency_sources.py` |
| Release build | `scripts/build_release.py::RUNTIME_ROOTS`, `scripts/build_release.py::REQUIRED_RUNTIME_FILES` |
| CI | `.github/workflows/ci.yml` (every PR and main), `.github/workflows/release.yml` (tags), `.github/workflows/skills-freshness.yml` (weekly) |

## Invariants

- **Never hand-edit generated or vendored content.**
  - `assets/artifacts/manifest.json` is generated by `scripts/build_artifact_manifest.py`.
  - The upstream skill directories in `assets/skills/` are vendored by
    `scripts/refresh_vendored_skills.py`.
  - `static/` is built from `frontend/`.
- **A skills bump moves three things together**, or boot rejects the skills. This is the
  order the weekly bump issue gives:
  1. `SKILLS_REF` in `server/bootstrap/install.py`.
  2. `scripts/build_artifact_manifest.py --write`.
  3. `scripts/refresh_vendored_skills.py --write`.

  Then update `assets/skills/SKILLS_SOURCE.md`.
- **Fail closed on checksums.**
  - A mismatched download is never executed or extracted.
  - `ARTIFACT_MANIFEST_PATH` may redirect an artifact's `source` only, never its version or
    digest.
- **Dependencies stay exact and public.** Every direct dependency in `pyproject.toml` is an
  exact `==` pin. Locks keep public registry URLs. Laptop proxies must not leak into
  committed files (`dependency_sources.py`).
- **The PEX is reproducible.** CI builds it twice and `cmp`s the bytes. It contains only
  `server/`, `static/`, `content/` and `assets/`, plus locked dependencies. Anything a runtime
  feature reads must live under those roots.
- **The paired app is separate.** `deploy/omnigent-app/` has its own `pyproject.toml` and
  `uv.lock`. The Omnigent pin also appears in `assets/artifacts/omnigent-0.21.0.lock`,
  `OMNIGENT_VERSION` and the manifest. Recent upgrade PRs (for example #155) move all of
  these together.

## Dependencies and consumers

- **Consumed by:**
  - every launch, through `server/bootstrap/install.py::ready` gates in
    `server/main.py::create_session`;
  - `/readyz`, through the `installers`, `supply_chain` and `release_pins` checks;
  - the attendee skills tree, through `server/user_content.py::_link_skills`;
  - Control Tower, which pins a release manifest digest.
- **Depends on:** network access to the upstreams (nodejs.org, GitHub, npm, PyPI, Launchpad)
  or a staged Volume mirror.

## Common mistakes

- **Bumping a pin without regenerating.** Changing a pin in `server/bootstrap/install.py`
  without regenerating the manifest. PR CI's `tests/test_artifact_manifest.py` cross-checks
  `SKILLS_REF`, but drift in the other checksums is caught by the weekly
  `skills-freshness.yml` job *(inferred from the workflow layout)*. Run
  `scripts/build_artifact_manifest.py --check` yourself.
- **Editing the wrong dependency file.** Adding a dependency to `requirements.txt` instead of
  `pyproject.toml`. CI regenerates the exports and fails on the diff, and
  `tests/test_release_artifact.py` checks `requirements.in`.
- **Running uv without `--frozen` on a laptop with a package proxy.** uv re-locks against the
  configured index and rewrites every URL in `uv.lock`; this was observed during the guide's
  inspection. CI's export diff and `dependency_sources.py` exist to catch it. Restore the
  lock with `git checkout -- uv.lock`, unless you meant to change dependencies.
- **Assuming the release builds on macOS.** It does not; use the CI `package` job.
- **Trusting the dated refresh record.** `docs/toolchain-release-refresh.md` is a dated
  October record; its version numbers are historical. Current pins are in code and the
  manifest.
- **Putting runtime files outside the runtime roots.** A file a runtime feature reads from
  `docs/` or `scripts/` works on a source deploy but is absent from the PEX.
